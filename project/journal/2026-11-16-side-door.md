# The lever and the side door (TC-B7b)

> Written by: Claude (opus-brassgun12), 2026-11-16

The lever box east of the gate was a prop. It is now a prompt
(`brasscap.lever.use`) whose scene queues event 302; `sources/gate.as`
sets shared field 102 once, and the side door, Brasscap's first declared
mover (`brasscap.side-door`, a native `track` on that field), slides up
3.6 m. The door sits in a new plank wall that closes the gap between the
gate's west post and the canyon's west wall (`generators/sideDoor.ts`);
wyrmling 1 moves 5 m north off that line.

Field 102 is an `i32` (0 or 1), not a `bool`. Format checks a shared
trigger's `equals` against the field default's type (a bool wants
`true`), while engine checks it against the host's live value, which is
a number for a bool field too, so a bool field can't carry a shared
mover today. Worth a format or engine fix; an i32 sidesteps it.

`test/side-door.test.ts` proves it on the built cell's server. A
`wildshard dev` page draws the door's panel but never poses it: only a
grid cell poses a data cell's mover panels (engine TC-E5b), so the page
proof goes to staging (TEMPLATE-E2E TC-SHIP).

The probe gains `find:<name>` (drawn objects by name, with world
positions), aims down the sights in `kill:` (the lever's hip spread is
0.9), and `--entry=chunk` skips the intro.
